# 使用文档

网关起来之后，它就是一个 OpenAI 兼容地址，后面接的是 Verdent 桌面端限免模型。

Base URL：`http://<地址>:7866/v1`  
鉴权：`Authorization: Bearer <config.json 里的 api_key>`

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/chat/completions` | 对话。`stream` true/false 都支持 |
| GET | `/v1/models` | 模型列表。默认只有限免，每项带 `is_free` |
| GET | `/status` | 账号池：健康 / 冷却 / 禁用、请求数、token |
| GET | `/healthz` | 健康检查，不鉴权 |

## 调用

先看限免模型：

```bash
curl http://127.0.0.1:7866/v1/models \
  -H "Authorization: Bearer 你的密钥"
```

非流式：

```bash
curl http://127.0.0.1:7866/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash-free","messages":[{"role":"user","content":"你好"}]}'
```

流式：

```bash
curl -N http://127.0.0.1:7866/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-5.3-flash-free","messages":[{"role":"user","content":"hi"}],"stream":true}'
```

不传 `model` 时默认 `deepseek-v4.1-flash-free`。

## 客户端

CherryStudio、Cline、NextChat、LobeChat、OpenAI Python SDK 都一样：

- 地址：`http://127.0.0.1:7866/v1`
- 密钥：`config.json` 的 `api_key`
- 模型：`/v1/models` 返回的 `id`

Python：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:7866/v1", api_key="你的密钥")
for chunk in client.chat.completions.create(
    model="deepseek-v4.1-flash-free",
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
):
    print(chunk.choices[0].delta.content or "", end="")
```

## 多账号

每个 Verdent 账号的限免窗口是独立的。换账号再跑一次：

```bash
./bin/verdent-login -auth ./auths/accounts.json -label second
```

网关约 15 秒内把新账号加进池。某个号触发 429 或限免窗口用尽，会冷却并自动换下一个健康账号，同一次请求最多试 3 个。

同一段对话按第一条 user 消息粘在同一个账号上，避免上下文跳号。

## 状态

```bash
curl http://127.0.0.1:7866/status -H "Authorization: Bearer 你的密钥"
```

`state`：

- `healthy`：可用
- `cooldown`：限流或限免窗口用尽，到期自动恢复
- `disabled`：token 失效且刷新失败，重跑登录

账号 id 会脱敏，token 不会出现在这个接口里。

## 和旧版的区别

旧版打 `api.verdent.ai`，用控制台创建的 team API key。那条链路消耗 credits，打不到桌面端 Free mode。

现在登录拿到的是桌面端 token，请求发到 `llm-proxy.verdent.ai`，`messages` 整段加密。所以模型名必须是限免目录里的 `-free` 模型；把付费模型名填进去，上游会按积分计费或直接拒绝。

## 客户端指纹

网关已把传输层指纹（TLS JA3、HTTP/2、ALPN、设备ID、请求头、会话行为）对齐到桌面端 Chrome 148 / Electron 42.7.0，上游无法区分网关请求与桌面 App 请求。这部分是自动的，使用时无需任何额外配置。详见 README 的「反风控：客户端指纹对齐」。

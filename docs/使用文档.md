# 使用文档

verdent2api 启动后是一个标准 **OpenAI 兼容** 端点，任何支持 OpenAI 协议的客户端都能直接接入。本文档讲怎么调、怎么配客户端、怎么排障。

Base URL 统一为：`http://<你的地址>:7866/v1`
鉴权：`Authorization: Bearer <config.json 里设置的 api_key>`

---

## 1. 接口一览

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/v1/chat/completions` | 是 | 对话补全，支持 `stream` |
| GET | `/v1/models` | 是 | 模型列表（上游模型 + 你配的别名） |
| GET | `/status` | 是 | 账号池快照（脱敏） |
| GET | `/healthz` | 否 | 健康检查 |

「是」表示当 `config.json` 设了 `api_key` 时需要带 Bearer；留空则不校验。

---

## 2. 快速调用

### 2.1 先看有哪些模型

```bash
curl http://127.0.0.1:7866/v1/models \
  -H "Authorization: Bearer 你的密钥"
```

返回里的 `data[].id` 就是可用模型名，填进下面的 `model` 字段。

### 2.2 非流式对话

```bash
curl http://127.0.0.1:7866/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<模型名>",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

### 2.3 流式对话（SSE）

```bash
curl -N http://127.0.0.1:7866/v1/chat/completions \
  -H "Authorization: Bearer 你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<模型名>",
    "messages": [{"role": "user", "content": "写一首五言绝句"}],
    "stream": true
  }'
```

流式返回标准 `data: {...}` 帧，以 `data: [DONE]` 结束，和 OpenAI 一致。

## 3. 接入常见客户端

所有客户端配置都是同一套：**API 地址填 `http://<地址>:7866/v1`，密钥填你的 `api_key`，模型填 `/v1/models` 里的名字。**

### CherryStudio
设置 → 模型服务 → 添加 → 选 OpenAI 类型：
- API 地址：`http://127.0.0.1:7866/v1`
- API 密钥：你的 `api_key`
- 模型：点「获取模型列表」自动拉取，或手填

### Cline / Roo Code（VS Code 插件）
API Provider 选 `OpenAI Compatible`：
- Base URL：`http://127.0.0.1:7866/v1`
- API Key：你的 `api_key`
- Model ID：填 `/v1/models` 里的模型名

### NextChat / Lobe-Chat 等
- 接口地址 / OpenAI Endpoint：`http://127.0.0.1:7866`（部分客户端会自动补 `/v1`，若报错则填 `http://127.0.0.1:7866/v1`）
- API Key：你的 `api_key`

### Python OpenAI SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:7866/v1",
    api_key="你的密钥",
)

resp = client.chat.completions.create(
    model="<模型名>",
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
)
for chunk in resp:
    print(chunk.choices[0].delta.content or "", end="")
```

## 4. 模型别名

如果上游模型名又长又难记，在 `config.json` 里配别名：

```json
{
  "model_alias": {
    "fast": "<上游真实模型名>",
    "smart": "<另一个上游模型名>"
  }
}
```

配好后：

- 客户端用 `fast`，网关自动改写成上游真实模型名再转发
- `fast` / `smart` 也会出现在 `/v1/models` 列表里，方便客户端选择

`model_map` 是同语义的旧字段名，区别是**只改写请求、不暴露到 models 列表**。

## 5. 读懂 /status

```bash
curl http://127.0.0.1:7866/status -H "Authorization: Bearer 你的密钥"
```

关键字段：

| 字段 | 含义 |
|---|---|
| `total_keys` / `healthy_keys` / `cooldown_keys` / `disabled_keys` | 池内 key 总数与各状态数量 |
| `total_requests` / `total_ok` | 累计请求数 / 成功数 |
| `total_prompt_tokens` / `total_completion_tokens` | 累计 token 消耗 |
| `keys[].state` | 单 key 状态：`healthy`（可用）/ `cooldown`（冷却中）/ `disabled`（已禁用） |
| `keys[].cooldown_until` | 冷却到期时间 |
| `keys[].last_err` | 最近一次错误 |

key 都做了脱敏（`sk-ver...3456`），不会泄露完整凭证。

## 6. 账号池行为（了解即可）

网关自动管理多个 key，你不用关心调度细节，但了解规则有助于排障：

| 上游表现 | 网关处理 |
|---|---|
| 401/403 鉴权失败 | 该 key **禁用**，需重新登录换 key |
| 402 或正文命中额度/余额不足 | 冷却 12h |
| 429 限流 | 冷却 60s |
| 连续失败达阈值 | 冷却 10m |
| 5xx | 直接透传错误，不入状态机 |
| 单次请求某 key 失败 | **自动换下一个健康 key 重试**（最多 3 个） |
| 全池不可用 | 返回 503 `no_healthy_account` |

同一段对话会固定用同一个 key（会话粘性），避免上下文跳号错乱。

---

## 7. 排障速查

**503 `no_healthy_account`**
池里没有可用 key。看 `/status`：是没 key（去登录）还是全被冷却/禁用（等冷却或换号）。

**401 `invalid_api_key`**
客户端带的 Bearer 和 `config.json` 的 `api_key` 不一致。

**流式响应卡住/不出字**
若走了反代，检查是否关了缓冲（Nginx 需 `proxy_buffering off`）。

**某模型报模型不存在**
先 `curl /v1/models` 确认上游确实支持该模型名，或检查别名是否配对。

**客户端不识别思维链字段**
`config.json` 里 `features.strip_reasoning` 默认 `true`，会移除流式帧里的 `reasoning_content`。如果你的客户端需要思维链，改成 `false`。

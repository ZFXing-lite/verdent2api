# 部署文档

本文档覆盖 verdent2api 从零到运行的完整部署流程，含本机、systemd、Docker 三种方式。

---

## 0. 前置条件

- Go 1.19+（仅本机源码构建需要；用 Docker 或预编译二进制则不需要）
- 至少一个可正常登录的 Verdent 账号（用于生成上游 API key）
- 一台能访问 `api.verdent.ai` / `login.verdent.ai` / `platform.verdent.ai` 的机器

> 项目零第三方依赖，纯 Go 标准库。

---

## 1. 构建

```bash
git clone https://github.com/ZFXing-lite/<仓库名>.git verdent2api
cd verdent2api
./build.sh
```

`build.sh` 会依次执行 `go vet` → `go test ./...` → 构建，产物落在 `./bin/`：

- `bin/verdent-server`：主网关服务
- `bin/verdent-login`：登录取 key 工具

只想快速编译不跑测试：`go build ./...`。

---

## 2. 登录并生成上游 API key

Verdent 登录带 Cloudflare Turnstile 人机验证，必须人工完成一次，无法自动绕过。

```bash
./bin/verdent-login                 # 默认监听 :17867
# 或自定义
./bin/verdent-login -listen :17867 -keys ./auths/verdent-keys.json -name my-key
```

浏览器打开 `http://127.0.0.1:17867`，输入邮箱密码、完成人机验证、点击登录。工具自动完成：

1. `POST login.verdent.ai/passport/login` → 拿登录态 cookie
2. `GET platform.verdent.ai/api/verdent/home` → 校验登录并取 `team_id`
3. `POST platform.verdent.ai/api/verdent/team/api-keys/create` → 创建 key
4. 追加写入 `auths/verdent-keys.json`（已有 key 不丢）

页面会显示一次明文 key。想要多号轮换，用不同账号重复登录几次即可。

## 3. 配置

```bash
cp config.example.json config.json
```

编辑 `config.json`，**至少把 `api_key` 改成一个随机长串**（这是客户端连本网关的密码；留空 = 不鉴权，任何人都能白嫖你的账号）。

生成一个随机密钥：

```bash
openssl rand -hex 24
```

完整配置项见 `README.md` 的「配置项」表。常用的几个：

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen` | `:7866` | 监听地址 |
| `api_key` | `""` | 网关鉴权密钥，**务必设置** |
| `model_alias` | `{}` | 模型短名映射，会暴露进 `/v1/models` |
| `pool.rate_cooldown` | `60s` | 429 冷却时长 |
| `pool.credit_cooldown` | `12h` | 额度不足冷却时长 |

## 4. 启动

### 4.1 本机直跑

```bash
./bin/verdent-server -config config.json
```

看到 `verdent2api x.y.z listening on http://127.0.0.1:7866` 即启动成功。

登录工具后续新建的 key 会被**自动热重载**进池（15s 粒度），无需重启服务。

### 4.2 systemd（长期运行推荐）

创建 `/etc/systemd/system/verdent2api.service`：

```ini
[Unit]
Description=verdent2api gateway
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/verdent2api
ExecStart=/opt/verdent2api/bin/verdent-server -config /opt/verdent2api/config.json
Restart=on-failure
RestartSec=3
# 也可用环境变量覆盖敏感项，避免写进 config.json
Environment=V2A_API_KEY=你的随机密钥

[Install]
WantedBy=multi-user.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now verdent2api
sudo systemctl status verdent2api
journalctl -u verdent2api -f      # 看日志
```

### 4.3 Docker

```bash
docker build -t verdent2api .
docker run -d --name verdent2api -p 7866:7866 \
  -v $PWD/auths:/app/auths \
  -v $PWD/data:/app/data \
  -e V2A_API_KEY=你的随机密钥 \
  verdent2api
```

两个挂载卷很关键：

- `auths`：凭证目录，挂出来才能在宿主机跑登录工具写 key
- `data`：池状态 `state.json`，挂出来才能重启不丢冷却/计数

环境变量覆盖（12-factor 友好）：`V2A_API_KEY` / `V2A_LISTEN` / `V2A_KEY_FILE` / `V2A_STATE_FILE`。

## 5. 验证部署

```bash
# 健康检查（无需鉴权）
curl http://127.0.0.1:7866/healthz

# 账号池快照
curl http://127.0.0.1:7866/status -H "Authorization: Bearer 你的随机密钥"

# 模型列表
curl http://127.0.0.1:7866/v1/models -H "Authorization: Bearer 你的随机密钥"
```

`/status` 里能看到每个 key 的状态（healthy/cooldown/disabled）、请求数、token 计数。

## 6. 安全加固（公网部署必读）

- **必须设 `api_key`**：否则端口暴露即等于账号裸奔。
- **前置 HTTPS 反代**：用 Nginx / Caddy 套 TLS，不要让 `:7866` 明文直接暴露公网。
- **限制来源**：反代层加 IP 白名单或 Basic Auth 双保险。
- **凭证文件权限**：`auths/verdent-keys.json` 建议 `chmod 600`，只有服务账号可读。
- **不要把 `config.json` / `auths/*.json` 提交进 git**：`.gitignore` 已默认忽略。

Nginx 反代示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:7866;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # 关键：SSE 流式不缓冲
    proxy_read_timeout 300s;
}
```

## 7. 常见问题

**Q: 所有请求返回 503 `no_healthy_account`？**
池里没有可用 key。跑登录工具生成 key，或检查 `auths/verdent-keys.json` 是否有内容、是否被全部禁用（看 `/status`）。

**Q: 登录后提示 `is_login=false`？**
可能是跨域 cookie 问题。把上游实际返回的 Set-Cookie 反馈给维护者定位。

**Q: 某个 key 变成 disabled 了？**
上游返回了 401/403（key 失效）。重新登录生成新 key 即可，热重载会自动接管；或在旧号恢复后手动改凭证。

**Q: 改了 config.json 要重启吗？**
要。config 只在启动时读一次。但**新增 key 不用重启**（热重载）。
